## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

## Architecture
- AI breakdowns are generated in `src/lib/breakdown.functions.ts` (public server fn, no sign-in, strict JSON schema mirroring `Breakdown` in `src/lib/types.ts`); keep the schema and type in sync so saved rows stay renderable.
- The problem log lives in browser localStorage (`src/lib/local-log.ts`) so the app collects no user information; the unused `public.problems` table is kept for a possible future accounts mode.
- Waiting-screen learning tips are bundled locally rather than generated by AI so they appear immediately without adding requests or generation latency.
- Waiting-screen questions and answer explanations stay local with the tips; interactions must not add AI requests or delay the result.
- Waiting questions use a device-local history of displayed question indices and random sampling without replacement; stop questions when the local bank is exhausted instead of recycling them.
- Render the six breakdown sections as shared preview flashcards opening scrollable detail dialogs, so workspace and saved problems remain consistent.
